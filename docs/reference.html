    Events

    OAuthConnected

    Conceptlz\AdobeSign\Laravel\Events\OAuthConnected, final, uses Dispatchable. Dispatched by the OAuth callback after the token is stored.

    PropertyTypeDescription
    $userIlluminate\Contracts\Auth\AuthenticatableThe signed-in user who connected
    $keystringThe token store key, from AdobeSignManager::userKey()
    $apiAccessPoint?stringThe account's API host, e.g. https://api.eu1.adobesign.com/

    WebhookReceived

    Conceptlz\AdobeSign\Laravel\Events\WebhookReceived, final, uses Dispatchable. Dispatched by the webhook route once per new notification; duplicates are already dropped. Listeners doing real work should implement ShouldQueue.

    PropertyTypeDescription
    $eventConceptlz\AdobeSign\Webhook\WebhookEventThe parsed notification: AgreementEvent, MegaSignEvent, WidgetEvent, LibraryDocumentEvent or UnknownEvent. Fields are listed on the Webhooks page.

    The adobe-sign:verify command

    adobe-sign:verify {--user= : Check this user's OAuth connection instead of the default client}

    Calls GET /users/me with the default client, or with forUser($user) when --user is given (a token key, e.g. 42 or team:7). On success it prints "Connected to Acrobat Sign." with the user's email, whether they are an account admin, and the account id, and exits 0. On any SDK exception, including MisconfiguredException, it prints the message and exits 1. 

    php artisan adobe-sign:verify
php artisan adobe-sign:verify --user=42

    EloquentTokenStore

    get(string $key): ?Conceptlz\AdobeSign\Auth\AccessToken

    The stored token for a key, or null.

    put(string $key, Conceptlz\AdobeSign\Auth\AccessToken $token): void

    Insert or update the row for the key (updateOrCreate).

    forget(string $key): void

    Delete the row. Not part of the TokenStore interface, and it doesn't revoke the token at Adobe; call AdobeSign::oauth()->revoke($token) first if that matters.

    MisconfiguredException

    Conceptlz\AdobeSign\Laravel\MisconfiguredException extends RuntimeException and implements the core's Conceptlz\AdobeSign\Exception\AdobeSignException, so a catch (AdobeSignException $e) covers it too. These are the messages it carries:

    MessageThrown byFix
    Set ADOBE_SIGN_INTEGRATION_KEY, or ADOBE_SIGN_AUTH=oauth.client()Add the key
    adobe-sign.auth is "oauth" but no user is signed in; use AdobeSign::forUser($user).client()Use forUser() in jobs, commands and listeners
    Set ADOBE_SIGN_CLIENT_ID and ADOBE_SIGN_CLIENT_SECRET to use OAuth.oauth(), forUser(), the OAuth routesAdd the OAuth app credentials
    Set ADOBE_SIGN_WEBHOOK_CLIENT_IDS (or ADOBE_SIGN_CLIENT_ID) to receive webhooks.webhookHandler(), the webhook routeAdd the allow-list
    ADOBE_SIGN_SIGNATURE_LEVEL must be ses, aes or qes; got "…".signatureLevel(), and so every client creationFix the value

    All other exceptions come from the core; see its errors page.

    Common questions

    Will my IDE autocomplete AdobeSign::agreements()?

    Yes. The facade's docblock declares every method with its return type, so PhpStorm, Intelephense and PHPStan/Larastan resolve AdobeSign::agreements()->create() to the core Agreements resource.

    Does the package fire events for individual signers or statuses?

    It fires one event type for all webhooks, WebhookReceived, and leaves interpretation to you. Check $received->event->event or use is(EventType::…) and isWorkflowCompleted(). The only other event is OAuthConnected.

    Can I extend AdobeSignManager?

    It isn't final, so you can subclass it and rebind it as scoped in your own service provider. Prefer composition where you can: most needs are covered by binding a ClientInterface or TokenStore, or by building a core client directly.

    Can I rename the package's routes?

    The names (adobe-sign.oauth.redirect, adobe-sign.oauth.callback, adobe-sign.webhook) are fixed; the URIs and middleware are configurable. The manager relies on the callback's name to build the default redirect URI.
